# Architecture (broad strokes)

Status: draft for approval. Hard-to-reverse choices are marked **[decide]**.

## Requirements that shape it
Functional: see `impact-map.md` and the `.feature` files.

Non-functional:
| NFR | Consequence |
|---|---|
| Fully offline, no accounts, no sync | One local SQLite file. No network code and no network entitlement at all. |
| History must stay private when the source is public | No data, mapping or secrets in the repo. Fresh install is empty. Import is a separate Mac tool with an ignored personal mapping. |
| Runs sideloaded in LiveContainer | Plain IPA, no special entitlements, no push notifications (reminders are an in-app tab). |
| Money must be exact | Integer minor units, never floating point. |
| Rules change often (refunds, cash, ledgers) | Rules live in a pure core tested without UI or simulator. |
| Backup is the owner's job | Single-file export and safe import are first-class features. |
| Small data (about 1,200 expenses a year) | No pagination, caching or indexes beyond the basics. Compute totals instead of storing them. |
| Accessibility | Dynamic Type, VoiceOver labels, 44 pt targets, chart plus list. |

## Decisions
| # | Decision | Why | Reversibility |
|---|---|---|---|
| 1 | **[decide]** Platform: native iOS, Swift, SwiftUI | Offline personal app, native feel (Apple UI guide) | Hard |
| 2 | **[decide]** Storage: one SQLite file via GRDB.swift | Plain SQLite file the owner can export, inspect and move; migrations and in-memory databases for tests. SwiftData and Core Data hide the file format and tie the importer to Apple internals. | Hard |
| 3 | **[decide]** Money: whole paise as integers (INR only). USD holding: cents plus a manual rate. | Exact sums; no float drift | Hard |
| 4 | **[decide]** Dates: calendar dates as `YYYY-MM-DD` text, no time zones | Expenses are dated days, never instants | Hard |
| 5 | **[decide]** Totals are computed, never stored or copied | Correcting one entry fixes everything; no sync bugs. Ledger balances, cash in hand, left to spend, card bills and net worth are all derived. | Medium |
| 6 | Modular monolith, no event bus yet | No requirement chains in time. Reminders are derived from data plus today's date, not scheduled. Add events only when a feature needs "after X do Y". | Easy |
| 7 | Core as a Swift package with no UI imports; SwiftUI app target generated by XcodeGen | Core tests run with `swift test` on the Mac in seconds, no simulator | Easy |
| 8 | No repository interfaces. Use cases call concrete GRDB-backed repositories; tests use a real in-memory database. | One implementation, so an interface would be premature. Only the clock is faked. | Easy |
| 9 | One-time importer is a Swift command-line tool on the Mac that reuses the core's schema and repositories | Same schema by construction; reads the ODS (a zip of XML) directly | Easy |
| 10 | **[decide]** Minimum iOS and app name: see open questions | Affects Charts and Observation APIs | Medium |

## Layers (dependency rule: arrows point inward)
```
SwiftUI views  ->  presenters / view models  ->  use cases  ->  domain (pure rules)
                                                     |
                                                repositories (GRDB)  ->  SQLite file
                                  clock, file picker, share sheet = thin adapters
```
- **Domain:** `Money`, `CalendarDate`, expense with its refund state machine, payment kinds, budget and net-worth calculators. No IO, no clock, no randomness.
- **Application:** one use case per user action (add expense, record received, add recurring items for a month, record payout, import backup). Takes a `Clock` and repositories.
- **Infrastructure:** GRDB repositories, migrations, backup and restore of the database file.
- **Presenters:** pure functions from query results to display rows (messages, groupings, share percentages). Views stay thin. Formatting of numbers lives in the app target.
- **Composition root:** one place builds the database, clock and use cases and hands them to screens.

## Key modelling choices
- **Expense** is an entity with a refund state (not refundable, pending, settled with an amount received). Invalid moves are rejected inside the entity; one test per allowed and forbidden transition.
- **Payment method** has a kind: bank, card, withdrawal, cash in hand, ledger. The kind alone decides what an expense affects (see impact map table). Creating a ledger creates its payment method.
- **Derived balances:**
  - Left to spend = salary + investment income + money received + borrowed - savings - repaid - net expenses of bank, card and withdrawal kinds.
  - Cash in hand = manual adjustments + withdrawals kept for myself - net cash expenses.
  - Ledger balance = its manual entries - net expenses paid from it. A refund on such an expense therefore returns to the ledger with no extra code.
  - Card bill = sum of net amount per card and month, minus the paid amount.
  - Net worth = available for allocation + investments + ledgers flagged as mine.
- **Recurring:** a template plus a unique (template, month) marker on the expense it created, so "add all due" can never duplicate.
- **Reminders** are queries: schemes maturing within 90 days, payouts expected within 7 days, unrecorded for the month.

## Broad-stroke data (not a final schema)
Tables: expenses, income entries, borrowings and repayments, payment methods, categories and sub-categories, recurring templates, upcoming items, ledgers and ledger entries, holdings, payout schemes, allocated funds, card bill payments, cash adjustments, settings (bank balance and its date, USD rate and its date). Version kept in `PRAGMA user_version` with an idempotent migration ladder.

## Delivery
- Source in a public repo; owner builds the IPA locally and installs it in LiveContainer.
- Data file lives in the app's own storage. Export via the share sheet; import via the document picker. Both validate the file and never touch data before confirmation.
- Risk: removing the app or its container deletes the data. Regular exports are the safeguard.

## Folder layout (feature first)
```
Package.swift                         core library + test target + importer tool
project.yml                           XcodeGen spec (generated .xcodeproj is git-ignored)
src/core/modules/<capability>/<feature>/   domain + use cases + repository for one feature
src/core/shared/                      money, dates, clock, database, migrations
src/app/modules/<capability>/<feature>/    SwiftUI screens and thin view models
src/app/CompositionRoot.swift
tests/<capability>/<feature>/         .feature file + specs (mirrors src)
tools/ods-import/                     one-time importer (+ personal/ ignored)
docs/design/budget-app/
```

## Build order
0. Walking skeleton: add one expense, see left to spend, on the simulator and as an installable IPA, with one UI smoke test.
1. Shared core: money, dates, clock, database, migrations.
2. Expenses, income, month budget, refunds.
3. **Importer for those sheets** so the owner can check real numbers against the spreadsheet early.
4. Recurring and upcoming.
5. Ledgers, portfolio, payment from a ledger.
6. Card bills; amount to repay.
7. Payout schemes and reminders.
8. Insights.
9. Cash in hand.
10. Backup and restore polish; importer for ledgers and portfolio.
